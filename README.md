## Οι σημαντικότερες αποφάσεις (όλες αναλυτικά στο `DECISIONS.md`)

- **Ένα ενιαίο Chen ER διάγραμμα σε ERD+** είναι το παραδοτέο (η εκφώνηση μιλά σε ενικό, σελ. 13-14). Τα 9 διαγράμματα ανά περιοχή στη σελίδα `mdms-er.html` είναι μόνο βοήθημα ανάγνωσης.
- **Απλό ER, όχι EER** (απόφαση 9/10/26, D32): η εκφώνηση λέει μόνο «Chen ER», και η Εργασία 1 έλεγε «ER – όχι EER». Άρα:
  - Οι 7 ρόλοι (CONSUMER, FIELD_TECHNICIAN, MARKET_USER, SYSTEM_ADMIN, SYSTEM_OPERATOR, TSO_OPERATOR, DSO_OPERATOR) είναι **weak entities του USER_ACCOUNT**, καθένας με identifying 1:1 συσχέτιση (IS_CONSUMER … IS_DSO), χωρίς partial key, κλειδί = UserID (D1, D2). Ένας λογαριασμός μπορεί να έχει πολλούς ρόλους. Ο κανόνας «κάθε λογαριασμός έχει τουλάχιστον έναν ρόλο» πάει στη Φάση Β.
  - SUPPLIER και AGGREGATOR είναι δύο ξεχωριστές κανονικές οντότητες. Ο MARKET_USER έχει WORKS_FOR_SUPPLIER και WORKS_FOR_AGGREGATOR, ακριβώς ένα από τα δύο με row CHECK (D30).
- Ο κανόνας της διάλεξης «η συμμετοχή της weak entity στις identifying συσχετίσεις είναι πάντα (1,1)» ισχύει και στις 21 identifying συσχετίσεις (`er-model/weak-entities-check.md`).
- **Σημειογραφία ERD+:** το ERD+ γράφει το (min,max) μιας οντότητας στην **απέναντι** άκρη της γραμμής. (1,1) ακριβώς ένα, (0,1) το πολύ ένα, (1,M) ένα ή περισσότερα, (0,M) οσαδήποτε. Στις αναδρομικές συσχετίσεις (μόνο PARENT_OF) το ERD+ δεν δείχνει cardinality, γι' αυτό υπάρχουν 2 Labels.
- Το ERD+ στη μετατροπή σε σχεσιακό ονομάζει τα FK με το όνομα του PK, οπότε κάποιοι πίνακες θα είχαν δύο στήλες UserID. Το `create.sql` έχει ήδη τα σωστά ονόματα (renames `fk` στο `model.js`). Το `node fksim.js` δείχνει ποιους πίνακες θα χαλούσε η αυτόματη μετατροπή του ERD+ (5), άρα **το σχήμα της Φάσης Α είναι το `create.sql`, όχι το αυτόματο του ERD+**.
- Ερωτήσεις για το εργαστήριο, ανοιχτές: C1-C7 (προθεσμία, αν διαγράφονται οι τελικές μετρήσεις, άθροισμα αθροιστικών μετρητών, διατήρηση ανά καταναλωτή ή μετρητή, αν ο ΛΣ είναι ο DSO, τι σβήνει το δικαίωμα στη λήθη, μετρήσεις μετασχηματιστών/απώλειες). Το μοντέλο δουλεύει με την απάντηση που γράφει κάθε C, και η αλλαγή είναι μικρή αν το εργαστήριο πει αλλιώς.

## Πώς ξαναπαράγονται και ελέγχονται (Node 22)

```bash
cd er-model
npm i                                   # @viz-js/viz, docx και (dev) playwright
node erdplus-check.js                   # "errors": [] = το .erdplus ταιριάζει με το model.js
node check.js                           # παραπομπές στο ../p.txt (γνωστές προειδοποιήσεις: S18 και S55 γιατί το pdftotext κολλά λέξεις σε αλλαγή γραμμής, S62 γιατί είναι λίστα κωδικών OBIS· το κείμενο υπάρχει στις σελ. 6, 10, 15)
node checkwhole.js
node fksim.js

# μετά από αλλαγή στο model.js:
node erdplus-export.js && node erdplus-check.js          # νέο αρχείο ERD+
node schema.js && node tests.js                          # νέα create.sql, drop.sql, test.sql
docker run -d --name mssql -e ACCEPT_EULA=Y -e 'MSSQL_SA_PASSWORD=<password>' -p 1433:1433 mcr.microsoft.com/mssql/server:2025-latest
MSSQL_SA_PASSWORD=<password> ./runtests.sh               # πρέπει "failed 0"
node build-schema.js && node build.js                    # οι δύο σελίδες HTML
```

Ελέγχθηκε στις 17/10/26 σε αυτόν τον φάκελο: το `erdplus-export.js` και το `schema.js` ξαναγράφουν ακριβώς τα ίδια `mdms-er.erdplus` και `create.sql` (byte προς byte), και το `erdplus-check.js` δίνει 0 σφάλματα.

Προσοχή: οι filtered UNIQUE indexes θέλουν `SET QUOTED_IDENTIFIER ON` σε κάθε σύνδεση που γράφει (το SSMS και οι οδηγοί PHP το βάζουν, στο `sqlcmd` δώσε `-I`).
