## Base data: `data/small/00_base.sql`

Generated by `data/gen/base.py` (fixed seed, so it always comes out the same). **Never edit the `.sql` by hand:**
change the generator and run `python data/gen/base.py`. IDs 1–999. Loads in one transaction.

| What | Content |
|---|---|
| Users | `admin`, `operator`, `consumer1`, `consumer2`, `tech1` (Approved), `tech2` (Pending), `dso1`, `tso1`, `supplier1`, `aggregator1`. One test password for all, in the file header. |
| Geography | 2 districts, 3 municipalities, 3 parishes |
| Catalogs | supply schemes (Standard, Net Metering, Net Billing), tariffs, service types, meter models, comm types, technician categories |
| OBIS codes | All 12 from the spec appendix, with `MinValid`/`MaxValid` |
| VEE rules | Range, Spike, Gap, LinearEstimate, VoltageBand + `RULE_FOR` |
| Grid | 6 geofences, transformer tree of 3 levels ([10-tso-transformers.md](10-tso-transformers.md)) |
| Customers | premises, holdings, bank accounts, contracts, invoices, a payment, a portfolio, a service request |
| Meters | 5 (4 Active, 1 Pending confirmation), installations, documents, phases |
| Readings | 1,102 raw: 18–19/11 validated, 20/11 00:00–05:45 **Pending** for VEE. 960 validated. Day aggregates. One unmatched packet + its event. |

## Large data: `data/large/*.dat` + `sql/import.sql`

Generated by `data/gen/large.py` (fixed seed; `python data/gen/large.py` from the repo root; it self-checks before writing).
Loads **after** `data/small/00_base.sql`. All IDENTITY IDs start at 100000. Usernames `lc_NNNNN` (consumers) and `lt_NNN`
(technicians), same demo password as the base data. Details and run order: [data/README.md](../data/README.md).

| Table | Rows |
|---|---|
| USER_ACCOUNT | 1,025 (1,000 consumers, 25 approved technicians) |
| GEOFENCE / TRANSFORMER | 44 / 44 (4 mid-level + 40 new leaves under base transformers 2 and 3) |
| PREMISE / HOLDING | 1,100 / 1,100 |
| BANK_ACCOUNT / SUPPLY_CONTRACT | 800 / 800 |
| INVOICE / PAYMENT | 2,400 (3 months per contract) / 1,600 |
| METER / METER_CONNECTED_PHASE | 1,000 Active / 1,500 |
| FIELD_TASK / METER_INSTALLATION | 1,000 Done installations / 1,000 Confirmed |
| TELEMETRY_PACKET | 280 (one per reading meter per day, tiny JSON) |
| RAW_READING / VALIDATED_READING | 30,912 / 30,912 (40 meters x 7 days x 96, 6 prosumers also 2.8.0) |
| METER_AGGREGATE / TRANSFORMER_AGGREGATE | 322 / 322 (Day rows) |

**Size cap:** each student database on the department server holds at most 27 MB of data (20 MB log), and system objects (catalog, procedure code) already use 16.5 MB. So the large set must stay under about 7 MB stored. The generator estimates it from measured bytes per row x 1.2 (now 6.8 MB) and refuses to write above 7 MB. Total 78,609 rows, still far above "thousands of rows". Import commits every ~2,000 rows (`GO`).

Import = run `sql/import.sql` in SSMS (`BULK INSERT` on the department server cannot see our files). Decisions B8, B9.
