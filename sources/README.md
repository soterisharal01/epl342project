# Η εφαρμογή PHP του MDMS-Cy (φάκελος `sources/`)

## Τι κάνει, σε 4 προτάσεις

Ο χρήστης ανοίγει τη σελίδα, γράφει το **username** και τον **κωδικό** του στο MDMS-Cy και πατά «Σύνδεση».
Η εφαρμογή ρωτά τη βάση ποιος είναι και τι **ρόλο** έχει (ένας ρόλος ανά username, όπως είπε ο καθηγητής).
Μετά του δείχνει **μόνο** τις σελίδες του ρόλου του, π.χ. ο καταναλωτής βλέπει τις σελίδες του `consumer/`.
Κάθε σελίδα μιλά με τη βάση **μόνο** μέσω stored procedures, ποτέ με SQL γραμμένη μέσα στην PHP.

## Τα αρχεία, ένα ένα

| Αρχείο | Τι κάνει (απλά) |
|---|---|
| `config.example.php` | Πρότυπο με τα στοιχεία σύνδεσης στη βάση. Το αντιγράφεις ως `config.php` και βάζεις τον κωδικό σου. Το `config.php` δεν ανεβαίνει ποτέ στο GitHub. |
| `db.php` | Η «γέφυρα» προς τη βάση. Ανοίγει τη σύνδεση, καλεί ένα procedure με `call_proc('sp_…', [τιμές])` και τυπώνει αποτελέσματα ως πίνακα (`print_table`). Αν η βάση πει λάθος, δείχνει στον χρήστη μόνο το ελληνικό μήνυμα των δικών μας procedures και κρύβει τα τεχνικά λάθη. |
| `auth.php` | Θυμάται ποιος έχει συνδεθεί (session) και ελέγχει ότι μια σελίδα την ανοίγει ο σωστός ρόλος (`require_role`). Έχει και την προστασία των φορμών (CSRF). |
| `layout.php` | Η κοινή εμφάνιση: πάνω μπάρα, μενού αριστερά, κάτω μέρος. Το μενού φτιάχνεται **μόνο του**: κάθε αρχείο στον φάκελο του ρόλου που ξεκινά με `<?php // MENU: Τίτλος` γίνεται link. |
| `index.php` | Η φόρμα σύνδεσης. |
| `login.php` | Ελέγχει τον κωδικό. Η βάση κρατά μόνο ένα «αποτύπωμα» (hash) του κωδικού και η PHP το συγκρίνει με `password_verify`. Αν ο λογαριασμός είναι σε αναστολή ή ο τεχνικός δεν έχει εγκριθεί, δεν τον αφήνει να μπει. Κάθε προσπάθεια γράφεται στο `AUDIT_LOG`. |
| `logout.php` | Αποσύνδεση. |
| `home.php` | Η αρχική μετά το login, με κουμπιά για τις σελίδες του ρόλου. |
| `profile.php` | Τα στοιχεία μου και αλλαγή κωδικού (για κάθε ρόλο). |
| `register_consumer.php` | Εγγραφή νέου καταναλωτή, χωρίς έγκριση (ΙΙΙ.1.1). |
| `consumer/10_premises.php` | Τα υποστατικά μου: λίστα, νέο υποστατικό (διεύθυνση, ΤΚ, WGS84, χρήση, ενορία), λήξη κατοχής (ΙΙΙ.1.1). |
| `consumer/20_bank.php` | Τραπεζικοί λογαριασμοί, και για ποιο υποστατικό είναι ο καθένας (ΙΙΙ.1.1). |
| `consumer/30_requests.php` | Αίτημα ελέγχου μετρητή ή αναφορά βλάβης, ιστορικό, ακύρωση, και η επίσκεψη τεχνικού όταν ανατεθεί (ΙΙΙ.1.3). |
| `consumer/40_billing.php` | Τιμολόγια (ποσό, πληρωμένο, υπόλοιπο), πληρωμή ολική ή μερική, ιστορικό πληρωμών (ΙΙΙ.1.3). |
| `_template.php` | Πρότυπο για νέα σελίδα. Το αντιγράφει όποιος φτιάχνει σελίδα στην περιοχή του. |
| `css/style.css`, `images/` | Εμφάνιση. |
| `admin/`, `operator/`, `consumer/`, `technician/`, `dso/`, `tso/`, `supplier/`, `aggregator/` | Οι σελίδες κάθε ρόλου. Ο καθένας γράφει μόνο στους δικούς του φακέλους. |

Τα procedures των σελίδων καταναλωτή είναι στο `sql/procs_consumer.sql` (tests: `sql/tests/test_consumer.sql`).
Τα procedures που χρησιμοποιεί ο σκελετός είναι στο `sql/procs_common.sql`:
`sp_auth_get_login`, `sp_auth_log_login`, `sp_auth_register_consumer`, `sp_user_get_profile`, `sp_user_change_password`.

## Γιατί είναι ασφαλές (για το κεφάλαιο ασφάλειας)

- **SQL injection**: η PHP δεν φτιάχνει ποτέ SQL από κείμενο του χρήστη. Στέλνει τις τιμές ως παραμέτρους `?` σε procedures.
- **Κωδικοί**: στη βάση μπαίνει μόνο `password_hash` (bcrypt), ποτέ ο ίδιος ο κωδικός.
- **XSS**: ό,τι εμφανίζεται περνά από `htmlspecialchars` (η συνάρτηση `h()`).
- **CSRF**: κάθε φόρμα έχει κρυφό κωδικό που ελέγχεται.
- **Ρόλοι**: κάθε σελίδα ελέγχει τον ρόλο (`require_role`) και **ξανά** τον ελέγχει και το procedure στη βάση.
- **Session**: νέο session id μετά το login, cookie μόνο για HTTP.
- **Καταγραφή**: logins (επιτυχημένα και αποτυχημένα), εγγραφές, αλλαγές κωδικού γράφονται στο `AUDIT_LOG`.

## Πώς τη βάζεις στον server του Τμήματος

1. Στη βάση σου τρέχουν ήδη, με τη σειρά: `create.sql` → `procs_common.sql` → … → `data/small/00_base.sql`
   (ή όλα μαζί: `python3 sql/tools/build_all.py` φτιάχνει το `sql/build/ALL.sql` για το SSMS).
2. Αντιγράφεις **τα περιεχόμενα** του `sources/` στο `~/public_html/mdms/` του λογαριασμού σου.
3. Εκεί αντιγράφεις το `config.example.php` σε `config.php` και γράφεις τον κωδικό σου (μόνο εσύ).
4. Δικαιώματα: φάκελοι 755, αρχεία 644 (και το `config.php`, αλλιώς ο web server δεν μπορεί να το διαβάσει), όπως στο Lab 7.
5. Ανοίγεις `https://students.cs.ucy.ac.cy/~<username>/mdms/` και μπαίνεις π.χ. με `consumer1`.
   Οι demo χρήστες και ο κωδικός δοκιμής είναι στο σχόλιο στην αρχή του `data/small/00_base.sql`.
